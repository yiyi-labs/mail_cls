# 模型设计与网页使用

任务是正常／垃圾邮件二分类。课程主线是“可靠邮件 → 清洗后的表 → Python 统计 → 特征 → 分类 → 错误分析”。网页不连接邮箱；输入文件只做本地分类，不自动进入训练。

## 三个页面

- **邮件实验室**：自行输入、上传 EML/TXT/CSV、统一数据表浏览；选模型分类，定位真实词元和特征，改写文字后用同一模型重新计算，也可比较多种方法。
- **模型对比**：同一批留出邮件上的准确率、Macro-F1、正常误拦和垃圾漏判；同时说明输入长度、参数量、训练方式及实测速度。训练曲线作为辅助详情。
- **数据分析**：来源与文字类型构成、类别分布、长度与质量、词语出现率；按来源／文字类型／长度／质量查错分，再打开具体邮件；可靠性曲线解释概率是否过于自信。

## 五种方法

| 方法 | 实际计算 | 训练范围 |
|---|---|---|
| B1 朴素贝叶斯 | Jieba 词 TF-IDF → 两类特征统计 → 分数 | 训练词表及分类器 |
| B2 逻辑回归 | 相同词 TF-IDF → 线性加权 → 分数 | 训练词表及分类器 |
| S_char13 多粒度 SVM | 正文词、字符 1–3 元组、主题词 TF-IDF → LinearSVC | 训练词表及分类器 |
| E1 Qwen 语义迁移 | 官方 Qwen3-Embedding-0.6B → 1024 维语义向量 → 逻辑回归 | 编码器冻结，仅训练分类器 |
| E2 MacBERT 专项微调 | hfl/chinese-macbert-base → 主题及正文首尾 → 二分类头 | 编码器与分类头监督微调 |

Qwen 的 0.6B 是编码器规模，选择它兼顾本机资源与语义表达；不是与 MacBERT 同参数量的实验。比较对象是完整分类方案。embedding 就是一封邮件的数值向量，语义接近的输入可能具有接近的向量；向量本身不是垃圾概率。

## 真实可视化的边界

分词、位置、IDF、向量值、线性权重贡献均来自当前模型与输入；神经热图来自实际前向计算中捕获的张量切片。动画是这些真实记录的回放，播放速度不表示真实计算耗时。线性贡献是向量值乘权重，不是概率变化或独立因果解释。神经张量也不是“这个词导致垃圾”的证明，文字改写实验只显示当前改动对当前输入的影响。

## 数据与分数如何理解

数据统一为 113,715 封，来源和数量见 `data/README.md`。训练更新参数；调参选候选；校准调整概率；策略选阈值；测试评价冻结后的方案。合并存放不等于合并训练用途，同模板仍按组隔离。发布前页面继续显示已发布模型的成绩。

分数接近 1 表示模型强烈倾向垃圾类别，可能存在数值饱和，也可能误判。训练邮件高分不能衡量泛化；应看独立留出数据的误拦、漏判和可靠性曲线。旧 TREC06C Test 已观察，新的重算只能称为历史回顾。

## 上传与恢复

上传 EML/TXT 单封或 CSV 批量。CSV 正文列 `body`／`正文` 必填，主题列 `subject`／`主题` 可选；最多 100 封、5 MiB。文件名及附带标签不进入分类特征。
